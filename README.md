# Нейросетевые методы NNF и NNFA обнаружения структурных выбросов: проверка на трёх наборах данных и влияние очистки на объём обучающей выборки

Л. Н. Ясницкий, А. Ю. Некрасов — НИУ ВШЭ — Пермь

Экспериментальное исследование нейросетевых методов NNF и NNFA, предложенных в препринте
Yasnitsky L.N., Goldobin M.A., Neverov A.R., Mezentsev A.S., Karakulova Yu.V., Dumler A.A.
*Neural Network Method for Structural Outlier Detection without Hyperparameter Tuning*
(Research Square, 2026, DOI [10.21203/rs.3.rs-10105267/v1](https://doi.org/10.21203/rs.3.rs-10105267/v1)).
Репозиторий содержит текст отчёта, программный код, данные и таблицы результатов всех экспериментов.

## О работе

Структурный выброс нарушает зависимость выходной переменной от входных, но ни по одному признаку не
выделяется. В методе NNF (Neural Network Filter) персептрон с одним скрытым слоем обучается на всей выборке,
и выбросами считаются наблюдения с наибольшей ошибкой обучения; число нейронов равно нижней границе интервала
из теоремы Арнольда – Колмогорова – Хехт-Нильсена. В методе NNFA (Neural Network Filter with Averaging)
ошибки усредняются по ансамблю сетей с разным числом нейронов.

Цель работы — проверить методы в условиях, не рассмотренных в препринте, и проверить предположение, что
очистка данных этими методами снижает требования к объёму обучающей выборки. Для этого:

1. программные коды авторов перенесены с PyTorch на NumPy, перенос сверен с оригиналом;
2. исследована зависимость качества обнаружения от мощности выбросов, методы сравнены с 15 классическими
   методами препринта и случайным лесом;
3. предложен алгоритм последовательного удаления выбросов с автоматическим критерием остановки;
4. измерено, как очистка влияет на точность итоговой модели и на объём выборки, нужный для заданной точности;
5. проверены устойчивость одиночной сети к выбору числа нейронов и выбросы во входных признаках.

Эксперименты выполнены на трёх наборах данных: Concrete Compressive Strength, California Housing и модельная
функция Фридмана № 1.

## Основные результаты

1. Перенос кода на NumPy воспроизводит препринт: NNF даёт F1 = 0,755 при опубликованном 0,760, код авторов
   на тех же данных — 0,760; разница меньше стандартной ошибки.
2. NNF и NNFA находят структурные выбросы, которые не видят методы без модели *y*(*X*). Порог обнаружимости
   NNFA — 0,67σ<sub>y</sub> на функции Фридмана, 1,23σ<sub>y</sub> на Concrete и 2,00σ<sub>y</sub> на
   California. Ни один метод не лучше NNFA на всех наборах, но на Concrete порог случайного леса с OOB-ошибкой
   ниже (1,02σ<sub>y</sub>).
3. Последовательное удаление с автоматической остановкой без знания числа выбросов работает для изолированных
   выбросов на уровне NNFA с известным числом выбросов, а при низком шуме находит и кластеры. На зашумлённых
   данных для кластеров критерий останавливается слишком рано.
4. Очистка NNFA при известном числе выбросов позволяет получить ту же точность итоговой модели на выборке
   меньшего объёма: примерно в 2–3 раза на Concrete, в 3,6–6,8 раза на функции Фридмана и от 2,7 до 10 и более
   раз на California. Без знания числа выбросов выигрыш заметен только при загрязнении около 5 %.
5. Устойчивость одиночной сети к выбору числа нейронов зависит от алгоритма и длительности обучения (RPROP,
   1000 эпох: 20 % пригодных значений; Adam: 98 %). Выбросы во входных признаках NNF и NNFA не находят.

При `RECOMPUTE = True` все эксперименты пересчитываются тем же кодом — около 8 ч на двух ядрах.

## Связь с кодом авторов препринта

Исходные коды авторов лежат в их репозитории <https://github.com/Astrohaker/OutliersDetectionResearch>
(лицензия MIT) и сюда не скопированы. Ядро `src/nnfa_core.py` повторяет их реализацию, перенесённую с PyTorch
на NumPy. Файл `Код_и_результаты/СООТВЕТСТВИЕ.md` показывает, какая логика авторов перенесена в какой модуль,
как она изменена и что добавлено нового. Для `src/exp1c_authors_code.py` нужен ноутбук авторов `!!!_14`: его
надо скачать из их репозитория в папку `Код_и_результаты/original_repo/`.

## Воспроизведение

### Windows через conda (рекомендуется, если pip не может скачать пакеты)

```powershell
winget install -e --id CondaForge.Miniforge3
```

Затем откройте из меню "Пуск" **Miniforge Prompt** и выполните:

```bat
cd /d "<путь к папке>\Код_и_результаты"
conda env create -f environment.yml
conda activate lab6
powershell -ExecutionPolicy Bypass -File .\run_all.ps1
```

Скрипт сам берёт Python из активного окружения conda. При медленном соединении перед созданием окружения
можно увеличить таймаут: `conda config --set remote_read_timeout_secs 120`.

### Windows через pip (PowerShell)

1. Установите Python 3.9+ с python.org и при установке отметьте "Add python.exe to PATH".
2. Откройте PowerShell в папке `Код_и_результаты`.
3. Выполните:

```powershell
powershell -ExecutionPolicy Bypass -File .\run_all.ps1 -Install   # первый запуск: пакеты + рисунки + проверки
powershell -ExecutionPolicy Bypass -File .\run_all.ps1            # рисунки и проверки по готовым таблицам
powershell -ExecutionPolicy Bypass -File .\run_all.ps1 -Force     # пересчитать эксперименты (~3 ч)
```

`-ExecutionPolicy Bypass` действует только на этот запуск и не меняет настроек системы. Уже посчитанные
эксперименты пропускаются; ключ `-Force` удаляет таблицы `results\` и считает их заново. Результаты
воспроизводимы: при тех же версиях библиотек пересчёт даёт те же числа (зёрна случайных чисел фиксированы).
Сверка с оригинальной реализацией на PyTorch выполняется, только если установлен `torch`; иначе эта проверка
пропускается.

### Linux / macOS

```bash
cd Код_и_результаты
pip install -r requirements.txt
bash run_all.sh                 # эксперименты, рисунки, проверки
```
